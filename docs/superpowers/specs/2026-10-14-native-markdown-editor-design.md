# 原生 Markdown 编辑与上传回显

## 目标与范围

将需求分析的文件正文编辑从 Tiptap 富文本改为 CodeMirror Markdown 源码编辑，保存文件原文，不再将 Markdown 转成 HTML 后写回。需求描述等本来就是富文本的字段不变。

## 交互

- 使用 CodeMirror 的 Markdown 语法高亮、行号、撤销重做、搜索与键盘编辑能力，提供源码、分栏、预览三种模式。
- 常用工具栏直接插入 Markdown 语法，图片上传插入 `![说明](地址)`。
- 预览使用现有 marked + DOMPurify，支持表格、任务列表、代码块等；HTML 清洗只作用于预览，不改写编辑源码。
- 上传成功后展示全部文件，保持文件为草稿，并直接在编辑器打开上传的 Markdown。未保存内容仍需先保存，失败时保留原草稿。
- 右侧文件名及更新时间所在的整个信息区域均可打开文件；Markdown 文件的操作改为明确的“打开编辑”，非 Markdown 保留“预览”。
- 沿用自动保存、串行保存、切换等待、导航保护、上传等待、撤销历史隔离与删除后恢复机制。

## 数据兼容

- 直接读取及保存 `content` 字符串；正文仍保存在现有工作区文件，数据库结构不变。
- YAML front matter、表格、任务列表、HTML 注释及原有 Markdown 语法不经过富文本模型转换。
- 历史文件如果已经保存为 HTML，则在源码区原样展示，并可正常预览；不自动覆盖或批量转换历史文件。

## 核实的上传问题

实际已上传文件的元数据、磁盘文件和内容接口正常。原上传流程将新文件标记为草稿，但默认列表只展示确认文件，且上传后没有打开动作。原文件行只有文件名文本按钮可点击，点击其余信息区域无动作。

本次增加真实文件选择上传、点击更新时间区域的端到端用例，而不只通过 API 预置文件。

## 验收

1. 通过页面上传 `.md` 后，文件自动出现、被选中，并回显完整 Markdown 源码。
2. 点击其他文件的信息区域或“打开编辑”，回显该文件而不写坏当前文件。
3. Markdown 源码编辑、格式快捷键、撤销重做及预览正常。
4. 保存后的本地内容仍是 Markdown，保留表格、任务列表、代码和 front matter。
5. 预览清洗危险 HTML，不改变文件原文；历史 HTML 不自动迁移。
6. 先前文件切换、保存失败、图片上传、导航及删除恢复测试继续通过。
