# 需求文档 Markdown 直存与所见即所得编辑

## 目标与范围

需求文档正文在磁盘上保存原生 Markdown，不再把编辑器 HTML 写回文件。编辑器保持现有 Tiptap 所见即所得形态（用户已明确不采用 CodeMirror 源码编辑器），读写时在 Markdown 与编辑器 HTML 之间双向转换。需求描述等本来就是富文本的字段不变。

## 交互

- 编辑器仍是富文本：工具栏、快捷键、撤销重做、图片上传与自动保存行为不变。需求列表里的描述弹窗与需求详情、文档、问题共用同一个编辑器组件，工具栏与行为一致。
- 打开文件时 Markdown → 编辑器 HTML；保存时编辑器 HTML → Markdown 写回同一文件。
- 图片上传插入的仍是编辑器图片节点；保存时还原为相对当前文档目录的 Markdown 图片语法。
- 沿用自动保存、串行保存、切换等待、导航保护、上传等待、撤销历史隔离与删除后恢复机制。

## 转换约定

- 使用 `turndown` + `turndown-plugin-gfm` 做 HTML → Markdown，`marked`（自定义 `Marked` 实例）做 Markdown → HTML。
- 标题用 ATX、列表用 `-`、代码块用围栏、强调用 `*`/`**`、链接内联。
- 任务列表：Markdown `- [x]` 与编辑器 `<li data-type="taskItem" data-checked>` 互转。
- 表格：Markdown 表格与编辑器表格节点互转；Tiptap 输出的 `colgroup` 由自定义规则跳过，单元格内的竖线转义。
- 删除线统一写 `~~…~~`；下划线没有 Markdown 语法，保留行内 `<u>`。
- 对齐与块级缩进没有 Markdown 语法：顶层段落/标题以行内 HTML 块（`style="text-align: …"`、`data-indent="N"`）原样保留；列表项内改用行内 `<span data-block="center:i2">` 承载（块级 HTML 会吞掉后续列表行），读入时再还原成段落属性。表格单元格不承载样式，按纯文本收敛。
- 空正文保存为空文件，不留只有换行的内容。

## 数据兼容

- 直接读写 `content` 字符串；正文仍保存在现有工作区文件，数据库结构不变。
- 早期以 HTML 保存的正文在读取时原样回显，首次编辑保存后即改写为 Markdown；不做批量迁移。
- 仅打开文件不会改写原文。

## 验收

1. 打开既有 Markdown 文件，编辑器正常回显标题、列表、表格、代码块与图片。
2. 编辑后保存，文件内容为 Markdown（标题为 `#`、图片为 `![alt](相对路径)`）。
3. Markdown 表格在编辑器内可编辑，保存后仍是 Markdown 表格，不降级为 HTML。
4. 图片引用始终是相对当前文档目录的路径，移动/改名后自动修正。
5. 旧 HTML 正文不自动迁移，首次编辑后才改写。
6. 文件切换、保存失败、图片上传、导航及删除恢复测试继续通过。
7. 段落与列表项的对齐、缩进在保存并重新打开后仍然生效，列表嵌套层级不被样式承载破坏。
