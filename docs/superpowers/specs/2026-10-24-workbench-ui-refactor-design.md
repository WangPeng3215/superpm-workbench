# superPM Workbench UI 重构设计

## 目标

将现有界面重构为「macOS 原生材质感 × 专业产品工作台」：结构清晰、密度适中、深浅色一致，玻璃效果只用于导航和浮层。视觉与交互外观可以调整，现有业务行为、数据契约和文件语义保持不变。

## 技术边界

- 保留 Vue 3、TypeScript、Vue Router、Element Plus 与 Tiptap。
- 不引入 Fancy UI、Tailwind、GSAP、Three.js 或第二套前端运行时。
- 不改变路由参数、API、SQLite、MCP、本地文件路径、需求状态流转和编辑器序列化。
- 保留当前侧栏图标可见性修复和更新提示端到端断言。
- 不修改 `updates/`，不递增版本，不提交、不推送、不发布。

## 设计系统

沿用项目现有语义变量并补齐字体、间距、圆角、控件高度、阴影、玻璃和动效 Token，避免同时维护 `--spm-*` 与现有变量两套名称。

- 品牌色：浅色 `#3370ff`，深色使用更浅的蓝色变体。
- 字体：系统字体栈，中文使用 Microsoft YaHei，编号和时间使用等宽数字。
- 间距：4/8px 基础网格；页面桌面边距 20–24px。
- 控件：常规输入与按钮 32–34px，表格表头约 38px、数据行约 46px。
- 圆角：控件 6–8px，面板 10–12px，浮层 12px。
- 动效：120–180ms，仅表达状态变化；支持 `prefers-reduced-motion`。
- 玻璃：侧栏、顶栏和浮层使用带不透明降级的背景；正文、表格和 Tiptap 不使用玻璃。

## 组件结构

- `App.vue` 保留认证、密码修改和路由组合职责。
- `AppSidebar.vue` 负责品牌、主导航、设置入口和折叠表现。
- `AppTopbar.vue` 负责功能页签、服务状态、通知、主题和用户入口。
- 现有 `styles.css` 保持全局入口，按 Token、Element Plus 映射、布局和通用组件分区。
- 业务页面继续拥有业务状态；只有重复且稳定的展示结构才抽取组件，不机械封装所有 Element Plus 控件。

## 全局框架

桌面使用 224px 侧栏和 52px 顶栏，主工作区独立滚动。1024px 以下侧栏收窄为 64px，隐藏文字但保留高对比图标、Tooltip 和可访问名称；更小窗口改为紧凑顶部导航。顶栏页签保留打开、关闭、路由回退和横向溢出行为，未选中项仍具有清晰 hover、focus 和 pressed 状态。

## 页面设计

### 需求列表

将多行筛选卡片改为紧凑工具栏：搜索、类型、状态、优先级和主要操作优先展示，时间条件进入可展开的筛选区域。保留所有过滤值和查询行为。表格减少纵向边框，表头不换行，名称列优先，编号使用等宽字体，行内编辑与新增行位置不变。

### 需求详情

头部以单行呈现编号、名称、阶段和保存状态，不增加 Banner。详情页签保留。需求详情采用主编辑区与属性侧栏，宽屏分别滚动，窄屏堆叠；属性侧栏可折叠以扩大编辑区。文档管理、问题记录和动态文档页签保持原业务结构。

### 文档、问题与 Tiptap

文档以紧凑文件列表和编辑工作区为主，保留上传、最终版、版本确认、路径和系统打开行为。问题描述与解决方案保持上下结构，元信息和保存状态清晰可见。Tiptap 工具栏统一高度、图标按钮、激活态、焦点态和深色配色，保存失败必须有文字反馈。

### 设置、规划页与登录

设置页采用左侧分类导航、右侧内容区，将本地存储、版本更新和功能模块放入同一工作区。规划页减少空卡片和无效说明。登录页与主应用共用品牌、控件和主题 Token，保留现有认证逻辑和回跳保护。

## 响应式与可访问性

验证 1440、1024、768、560、375px；页面本身不得横向溢出，宽表格只允许在表格容器内滚动。所有图标按钮具有名称，键盘可完成导航、页签关闭、筛选和编辑；focus-visible 清晰，状态不只依赖颜色，触屏点击目标至少 44px。

## 验证

每阶段运行相关测试，最终运行 `npm run typecheck`、`npm test`、`npm run build` 和 `npx playwright test`。真实浏览器覆盖深浅色、上述宽度、核心导航、需求增删改、详情保存、文档编辑与刷新、问题记录、文件上传和真实复制粘贴。不得直接操作数据库或以合成剪贴板事件替代真实交互验收。
