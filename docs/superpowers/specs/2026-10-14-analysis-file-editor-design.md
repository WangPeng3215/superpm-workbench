# 需求分析文件回显设计

## 已确认的交互

点击右侧 Markdown 文件，在左侧编辑器打开该文件；后续修改自动保存回原文件，而不是导入或覆盖默认分析记录。

## 当前数据来源

- `requirement_files` 表只保存文件 ID、所属需求、阶段、分类、显示名称、实际文件名、确认状态和时间。
- 正文通过 `RequirementFileService.content` 从工作区文件读取，通过 `saveContent` 写回文件。
- 默认分析记录位于 `workspace/requirements/<需求 ID>/analysis/分析记录/analysis-record.md`，工作区根目录可以通过环境变量配置。
- 现有编辑器是富文本编辑器：读取 Markdown 时转成 HTML，编辑后写回 Markdown（后续迭代已切换为 Markdown 直存，见 `2026-10-14-native-markdown-editor-design.md`）；本次不更换编辑器。

## 方案

1. 用完整的当前文件对象代替固定的默认文件 ID，读取和保存均使用该对象的需求 ID 与文件 ID。
2. 根据实际文件名识别 `.md`、`.markdown`，不依赖可重命名的显示名称。默认的“分析记录”没有显示扩展名，也允许点击。
3. 文件名使用可键盘操作的按钮，当前文件突出显示；编辑器标题旁展示当前文件名称。
4. 打开文件前等待正在进行的图片上传、清除防抖任务并完成当前文件保存。保存请求串行执行，保存期间新增的修改也必须完成后才切换；目标文件读取完成后再次排空源文件修改。
5. 切换期间锁定编辑器及文件修改操作，避免重复打开和交叉写入；打开同一文件不重置正文或编辑历史。
6. 保存失败不切换、不丢弃草稿；读取失败保留当前文件与内容，显示已有错误提示，并允许重试。
7. 切换文件重新创建编辑器实例，隔离撤销历史。切换阶段、需求或离开详情页前等待面板保存，失败阻止切换；切换需求重新创建面板，异步响应不能回写已经销毁的面板。
8. 重命名、确认状态切换和筛选不重置编辑内容。删除当前文件前等待上传和保存结束，删除后清空编辑器并打开默认分析记录；列表刷新失败保留待回退状态，下次刷新成功后恢复，不使用已删除的文件 ID。
9. 非 Markdown 文件继续使用原有预览入口，不进入编辑器。未接入文件面板的其他阶段保持不变。

## 验收

- 默认分析记录和上传的 Markdown 文件均能回显；只打开文件不触发正文写入。
- 编辑后 API 读回的是所选文件的新内容，默认分析记录不被覆盖。
- 防抖期间及请求进行中切换文件，旧文件的最后一次修改仍能正确保存。
- 保存失败阻止切换；读取失败保留原内容。
- 阶段切换和页面导航同样等待保存；延迟完成的图片上传不会在文件切换时丢失。
- 删除默认文件后即使遇到一次列表刷新失败，恢复网络后的成功刷新也能重新回显默认文件。
- 选中文件重命名、切换筛选后仍正确显示；删除当前文件后回到默认记录。
- 非 Markdown 文件不显示打开编辑按钮。

不修改已有数据库或用户工作区文件，不创建分支或提交。
