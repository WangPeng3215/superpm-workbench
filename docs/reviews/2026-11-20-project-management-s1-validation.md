# 项目管理 S0/S1 实施与验证记录

日期：2026-11-20（Asia/Shanghai）。分支：`codex/project-management-v1`。
状态：S0/S1 已实现并通过本阶段验收；S2—S4 尚未实施。

## 本批交付

本批实现初版项目维护、成员协作和需求归属，对应[开发总纲](../superpowers/plans/2026-11-19-project-management-v1-development.md)的 S0/S1。

- 项目：仅名称必填；列表搜索、视图与排序；基本信息自动保存；启动、暂停、恢复、取消、取消后重开，以及已取消/已结项项目的归档/解除归档。S1 尚无正式结项入口。
- 成员：搜索有效账号、兼任多个角色、指定主要项目/产品负责人、编辑角色和移除成员。最后负责人和未完成需求责任未移交时拒绝破坏性调整。
- 需求：项目内创建；全局按项目/未关联筛选；沿用原有两级表格、排序、置顶和唯一详情地址；需求负责人、开发负责人和验收标准自动保存。
- 旧需求加入项目：私人主需求整树预览，再明确确认；预览绑定账号、项目版本、需求树版本和资源指纹，5 分钟失效；不搬目录、不重排编号。
- 协作保护：整数对象版本、正文哈希、冲突冻结与会话草稿、统一关签保存、成员撤销后鉴权与缓存清理、命令重试幂等。
- 资源：问题、活动、文档、链接、旧文件、记忆、目录和图片按真实需求归属授权；旧的无账号绑定 MCP 默认不能访问项目域。
- 事件：后端已记录项目命令与变更事件并提供分页查询 API；动态界面属于 S4，当前页签标明后续开放。

不含 S2 项目任务/工时、S3 正式交付/验收/结项、S4 完整概览、资料聚合与动态界面。默认交付目前仅为数据库计划容器，界面不伪造交付进度。

## 独立审查与联调修正

后端独立审查覆盖项目服务、集中授权、需求服务/仓储、迁移、个人关联查询、MCP 调用边界及 HTTP 入口；前端独立审查覆盖保存队列、关签、版本透传、会话草稿和成员失权。

本批审查/浏览器联调实际发现并纳入修正的问题：

- 未结束项目可直接归档、需求跳阶段/退回缺少原因校验。后端先补复现测试，再收紧规则并同步 UI。
- 项目需求 DELETE 漏传对象版本，导致确认后返回 428。补齐 API 与调用点，并验证真实删除。
- 需求详情初载草稿与保存基线共用对象，导致 dirty 恒为 false。改为独立快照，真实浏览器验证编辑确实产生 PATCH。
- 行内权限复查把 401/503 当成明确失权清草稿。区分暂不可用、登录失效与 403/404/明确角色降级，前者暂停并保留草稿。
- 文档和问题编辑器缺少会话草稿，以及默认评论重试键不稳定。补账号/项目/需求/实体隔离和恢复版本检查，评论不确定失败重试复用键。
- 完整旧功能回归发现两处资源联调问题：单文件 404 被误判为整个需求失权，以及纯读取文件无条件递增元数据版本、使原列表版本的重命名触发 409。分别改为 404 时复核父需求授权后局部清理，以及元数据未变化的读取不递增版本；保留原有两个失败用例，另补重复读取、外部修改和问题被他人删除的回归。

上述修正已纳入下面的最终全量回归；审查覆盖不等于穷尽整个仓库的缺陷。

## 实施差异与限制

- 项目 SQL 与事务集中在 `services/projects.ts`，未另建 repository；自动保存 helper 实际文件名为 `features/editing/versioned-autosave.ts`。
- S1 责任交接采用先在需求详情转移责任，再修改成员/角色；未提供多对象一次提交的批量移交接口。最终角色变更事务仍重验责任，不依赖页面预检。
- S1 只允许取消状态重开；正式结项检查与 closed 状态重开在 S3 实现。已取消项目解除归档后仍是已取消，需显式重开才能继续写入。
- 刷新草稿为当前浏览器标签页的 sessionStorage；不能承诺清缓存后恢复。存储失败会提示。失权后不继续提供可恢复的项目正文。
- 项目命令和默认问题评论的待重试幂等键保存在当前页面的 JavaScript 内存；网络异常、408、5xx 后原操作重试复用，成功或确定的 4xx 后释放。尚未提供跨刷新恢复命令键，不能据此承诺刷新后重做命令也完全去重。
- 同一服务实例内协作，未实现多套本地部署的数据同步；没有变更监听地址或开放公网。
- 迁移验证仅使用临时库和临时工作区；未操作真实业务库或个人原型。不能用旧版 1.2.0 直接打开已启用共享的库。
- 更新器 BUG-001/002 仍是正式迁移发布的阻断项；本轮未改版本、未提交、未推送、未发布或部署。
