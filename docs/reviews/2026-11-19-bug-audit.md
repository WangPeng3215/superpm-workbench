## 复现证据、根因与建议

### BUG-001：HTTP 服务停止路径缺少进程身份验证

- 前提：原服务异常退出，runtime/server.json 残留，旧 PID 被复用，用户执行强制更新。不是 MCP 身份检查路径。
- 隔离复现：将登记 PID 指向自行创建的无关 HTTP fixture，fixture 不因关闭请求退出；约 10 秒后被实际更新器结束，victimAliveAfterUpdater=false。没有结束真实用户进程。
- 根因：stopServer 只检查 PID 存活，超时直接 taskkill /PID /T /F，未核对创建时间、可执行文件或服务入口。
- 建议：强杀前验证进程身份；无法确认归属时中止并提示，复用 MCP 停止路径的保守检查策略。

### BUG-002：更新器与应用的数据路径解析不一致

- 隔离复现：SUPERPM_DATA_DIR=store，真实 SQLite 在 home/store。迁移将测试值从 before 改成 migrated 后抛错。
- 实际结果：旧测试程序恢复到 0.1.0，状态为 rolled-back；数据库仍是 migrated，backups 目录不存在。日志先提示跳过备份，后提示已恢复旧程序与更新前数据。
- 根因：备份前硬编码检查 home/data/superpm.sqlite；恢复硬编码该数据库路径和 home/workspace；没有 backup 时直接返回，后续仍报告完整回滚。应用支持的实际路径见 [config/index.ts:147](D:/project/superPMWorkbench/apps/server/src/config/index.ts:147)。
- 建议：统一使用真实数据库、工作区路径；已有数据但没有有效备份时阻断升级；分别验证程序和数据回滚结果。
- 边界：实际复现了自定义数据库目录；自定义工作区恢复路径硬编码由源码确认，没有操作真实工作区进行恢复。

### BUG-003：SQL 掩码导致插入点越过字符串字面量

- 实际调用：普通用户作用域下执行真实 DailyTaskService.stop，抛出 SqliteError: near "and": syntax error；堆栈经 scope.ts 到 daily-tasks.ts 的 closeEntry。
- 根因：掩码将字面量替换为空格，trimInsertPoint 又在掩码上回退空白，最终把用户条件插入原表达式内部。
- 业务 SQL 示例：[停止 UPDATE:583](D:/project/superPMWorkbench/apps/server/src/services/daily-tasks.ts:583)、[活动任务查询:857](D:/project/superPMWorkbench/apps/server/src/services/daily-tasks.ts:857)、[文件状态统计:405](D:/project/superPMWorkbench/apps/server/src/services/artifacts.ts:405)、[文件搜索:2046](D:/project/superPMWorkbench/apps/server/src/services/artifacts.ts:2046)。
- 建议：使用原 SQL 的可靠 token 边界或可验证的解析方案，补充普通账号、尾部字面量和 ESCAPE 用例。超管路径不同；文件调用检查了 SQL 改写及源码，没有逐项做完整页面复现。
- 修复复核（2026-11-20）：插入点改为扫描原 SQL 的完整 token，保留字符串字面量与 ESCAPE，且把追加条件放在尾部行注释／块注释之前；ORDER/LIMIT 参数继续保持原位置。
- 红绿证据：新增真实 SQLite 执行用例先复现 `near "and": syntax error`，修复后 SELECT、UPDATE、DELETE 的尾部字面量、ESCAPE、注释和 ORDER/LIMIT 用例通过。`npx vitest run apps/server/tests/scope.test.ts` 共 22 项通过。
- 同步封堵：补测还发现顶层 OR 的原谓词未加括号时可能绕过追加的账号条件；测试先读到另一账号行，修复为先整体括起原谓词再追加条件后，跨账号 SELECT、UPDATE、DELETE 均被隔离。上述验证在内存测试数据库执行，未操作真实工作区。

### BUG-004：引用解析结果没有因本地编辑而失效

- 浏览器复现入口为优化点详情。挂起 /requirements/references，输入“解析引用期间输入的最新正文”，再释放响应。
- 实际结果：编辑器恢复初始正文和更新后的引用名称；继续输入并保存，PATCH 中也没有此前新输入的正文。
- 根因：contentSeq 只在外部内容解析时递增，本地输入没有使旧请求失效；返回后直接 setContent 替换整篇。
- 建议：本地编辑推进修订号，丢弃旧响应，优先只更新引用节点属性。公共编辑器被多个入口复用，本轮没有逐入口复现。
- 修复复核（2026-11-20）：公共编辑器在本地输入时推进内容修订号，迟到的引用解析不得对新修订调用 setContent。纯修订守卫测试与 `tests/e2e/project-collaboration.spec.ts` 的真实详情页延迟引用场景均已通过局部回归；最终全量记录见 [项目管理 S0/S1 验证记录](2026-11-20-project-management-s1-validation.md)。未将优化点保存响应覆盖问题 BUG-005 混为本项已修复。

### BUG-005：保存返回后无条件重建优化点表单

- 浏览器复现：输入第一版并保存，挂起 PATCH；正文仍 contenteditable=true，继续输入第二版，再释放响应。
- 实际结果：正文恢复第一版，脏标记数为 0；唯一 PATCH 只包含第一版。
- 根因：富文本未跟随 saving 禁用；旧响应更新 point 与 updatedAt，触发表单 key 变化并清除 dirty，未判断新修订。
- 建议：保存期间统一禁用编辑，或通过修订号与快照保留请求期间的输入，避免覆盖新草稿和错误清除 dirty。

### BUG-006：便签本地 refs 未同步刷新后的 props

- 浏览器复现：初始正文“最初便签正文”；模拟其他会话改成“外部修改正文”；刷新后仅修改标题。
- 实际结果：刷新 API 已返回新值，textarea 仍旧；标题 PATCH 仍包含旧 content，覆盖服务器新正文。
- 根因：稳定 clientKey 复用卡片组件，本地 refs 仅初始化一次；保存提交全部字段。
- 建议：无草稿时同步新 props，有草稿时处理冲突；只 PATCH 变更字段，并配合版本检查。

### BUG-007：便签卸载保存失败无法阻止导航

- 浏览器复现：PATCH 固定返回 503，输入新正文后切换到优化点，再回便签。
- 实际结果：记录到 4 次失败请求，离开确认框为 0；返回后只剩旧正文。
- 根因：页面没有离开路由前的统一 flush／失败拦截；卸载时异步 triggerSave 没有等待，也没有持久草稿恢复。
- 建议：离开前等待保存，失败时留在页面或由用户明确放弃；增加关闭保护与本地草稿恢复。

### BUG-008：系统身份下配额聚合缺少 user_id

- 内存 DB 固定日期 2026-11-19：A 有 07:00–14:00 共 7 小时完成工时，B 从 14:00 开始。B 自身作用域返回 autoEndAt=18:00。
- 实际结果：系统在 15:01 reconcile，将 B 在 15:00 关闭，endReason=daily_limit，B 仅计时 1 小时。
- 根因：系统身份不会自动按用户过滤，completedSecondsForDate 又未显式指定活动记录所属 user_id。系统启动和每 15 秒调用见 [app.ts:171](D:/project/superPMWorkbench/apps/server/src/app.ts:171)。
- 建议：配额始终按记录所属账号聚合，增加系统定时器下的多账号并行测试。

### BUG-009：重叠检查只查询 completed

- 同一账号：任务甲原完成记录 08:00–09:00；任务乙从 10:00 计时中；当前 10:30。甲校正为 09:30–10:15 成功，重叠 900 秒。
- 根因：others 查询仅含 status=completed，未覆盖 active。
- 建议：将活动记录纳入区间校验，明确其有效结束时间，防止重复计算工时。

### BUG-010：结束时间和结束原因使用不同判断

- 固定时间复现：09:00 开始，09:10 手动 stop，duration=600，但 endReason=daily_limit，应为 manual。
- 根因：endedAt 区分了当前时间和自动边界，传给 closeEntry 的 reason 却始终为 boundary.endReason；也可能误记 auto_18_00。
- 建议：未达到自动边界使用 manual；达到边界才写自动原因。展示位置见 [TimeEntryDialog.vue:80](D:/project/superPMWorkbench/apps/web/src/features/daily-tasks/TimeEntryDialog.vue:80)。

### BUG-011：用空备份 ID 获取目录

- 实际命令结果：无备份时普通 list 退出码 1，stderr 为“[backup] 非法备份 ID：”；JSON 分支正常。
- 根因：空列表提示调用 resolveBackupDir(homePath, 空字符串)，而解析器明确拒绝空 ID。
- 建议：展示备份根目录，不用空 ID 解析具体备份；补充空列表 CLI 测试。

### BUG-012：测试未固定业务时钟

- 本次约 21:55 执行，业务已禁止开始计时，user-isolation.test.ts:362 期望 200、实际 409；E2E 在晚间直接跳过。
- 建议：注入固定时钟，单独覆盖 18:00、8 小时上限及多账号场景。修正时钟后仍需检查 BUG-003 等后续路径，不能保证只改时钟就让全部测试通过。
- 局部处理（2026-11-20）：容器允许注入 dailyTaskNow，`user-isolation.test.ts` 固定到业务时间内执行，当前后端回归通过。未修改晚间 E2E 的主动跳过，也未顺带修复 BUG-008/009/010；本项继续标为部分处理。

此前关于“手工完整包覆盖也会自动创建 pre-update 备份”的说明不准确。
